## 核心思路

**不靠 AI 画的引导元素，靠脚本找内容**。所有抠图策略的基础假设：

1. 生成图是**纯白底 + N 个内容块**，中间有白色间隔
2. 没有网格线、没有锚点色块、没有文字标签
3. 内容块之间可以不等间距、不等大小，只要有白色间隔就能切

这样脚本完全不依赖 AI 的空间规划准确性，鲁棒性拉满。

## 模式 A：bbox 等分（默认）

### 何时用

- 生成图**行高、列宽基本均匀**（3×3 / 4×4 没问题，5×5 大多数情况也可以）
- 内容块围绕画布中心均匀分布
- 要求简单快速

### 算法

```
1. 找整图 content bbox（所有非白像素的外接矩形）
2. 在 bbox 内按 GRID × GRID 均匀等分
3. 每个 cell:
   - 白色像素 → 透明
   - 按 alpha > 0 找 tight bbox 裁紧
   - 保存为 {idx}_{name}.png
```

### 参数

```python
BG_THRESHOLD = 240  # RGB 全部 > 此值算背景（透明）
PAD = 8             # 裁紧时保留的 padding 像素
```

### 局限

- 不适合行高不均的情况（5×5 末行压缩时会切错）
- 如果某个角色占的空间特别大（比如春丽高踢），其他 cell 可能被挤占

## 模式 B：密度扫描（应对不均匀）

### 何时用

- **5×5 或更高密度**，出现明显的行高/列宽不一致
- 内容块非对称分布（有高踢、大姿势、异形 pose）
- bbox 等分后发现抠出来的图有「上一格的脚」或「下一格的头」

### 算法

```
1. 沿 Y 轴扫描每行的"非白像素数"，画出密度曲线
2. 连续高密度段 = 一行内容，低密度段 = 行间白色间隔
3. 阈值切分得到每行的 y0/y1
4. 在每行内沿 X 轴重复扫描，得到每列的 x0/x1
5. 组合得到 N×M 个精确 cell 坐标（非等分）
6. 每 cell：白→透明 + 裁紧 + 保存
```

### 参数

```python
BG_THRESHOLD = 240       # 非白判定阈值
ROW_DENSITY_MIN = 50     # 一行至少这么多非白像素才算有内容
SEGMENT_MIN_HEIGHT = 30  # 一段内容至少这么高才不算噪点
```

### 优势

- 对任何不均匀网格都鲁棒
- 允许不同 cell 有不同的实际尺寸
- 即使未来遇到 6×6 / 7×7 的不规则生成也能切

### 代价

- 脚本稍复杂（多一层扫描）
- 需要内容块之间有**明确的白色间隔**（至少 5-10px）

## 决策流程

```
收到网格图
   ↓
第一次直接跑 bbox 模式（最快）
   ↓
检查结果：contact sheet 看是否整齐
   ↓
├─ 整齐 → 结束
└─ 发现偏移/切错 → 切 density 模式重跑
```

90% 情况 bbox 模式够用。只有 5×5 以上或有特殊 pose 时才需要 density。

## 阈值调优手册

### 背景阈值 BG_THRESHOLD

- **默认 240**：适合大多数白底素材
- **调到 245**：如果背景有很轻微的灰色/米色染色（中文卡米色纸张容易出现）
- **调到 230**：如果背景偏灰、或有纸张纹理

### 裁紧 padding PAD

- **默认 8**：视觉舒适
- **调到 3**：需要紧凑裁剪（比如做 icon 字库）
- **调到 15**：需要留呼吸感（比如做卡牌封面）

### 中文内容的特殊处理

中文成语卡、古诗卡的背景通常是**米色/米黄色纸**（非纯白），直接用 BG_THRESHOLD=240 会漏抠。

**方案**：
- 把背景判定改为 **「低饱和度 + 高亮度」** 双条件
- `luminance > 220 AND saturation < 25` 视为背景
- 这能精确区分"米色背景"和"黑色中文字"

脚本中已实现，见 `extract_grid.py` 的 `--mode=bbox-chinese` 选项。

## 故障排查清单

| 症状 | 可能原因 | 解法 |
|------|---------|------|
| 抠出来整张都是原图 | bbox 没找到，背景不是白色 | 调低 BG_THRESHOLD，或检查是否是米色纸张 |
| 内容被切一半 | 网格不均匀，bbox 等分失败 | 切 density 模式 |
| 头部/手臂/武器缺失 | 连通域分析误判独立部件为杂点 | 脚本默认不启用连通域，若启用则增大膨胀半径 |
| 角色有彩色但被误删 | 背景阈值太松把浅色当背景 | 提高 BG_THRESHOLD 到 245+ |
| 网格线残留在结果里 | AI 画了不该画的网格线 | **先修 prompt**（加 `no grid lines`），而不是修脚本 |
| 锚点色扩散到角色身上 | 脚本在全图找红/蓝锚点像素 | 锚点检测要限制在画布四角 100×100 局部区域内 |
| 每张 PNG 尺寸都相同 | bbox 没有正确收紧 | 检查是否有全局性的浅色残留未被判为背景 |
| 最后一行被切斜 | 5×5 末行压缩 | 切 density 模式 |

## 进阶技巧

### 技巧 1：彩色内容的边缘软处理

纯黑 icon 的边缘很硬，白→透明的二值化阈值就够。但彩色内容（角色、卡牌）边缘有抗锯齿，生硬二值化会有锯齿感。

**软处理**：
```python
# 近白色但不纯白的像素，按亮度给部分透明度
near_white = (luminance > 225) & (saturation < 15) & ~is_white
fade_alpha = ((255 - luminance).clip(0, 30) * 255 / 30)
rgba[near_white, 3] = fade_alpha[near_white]
```

已实现在 `extract_grid.py` 中，自动启用于 RGBA 输出。

### 技巧 2：连通域过滤（慎用）

如果图里有**明显的黑色 1px 网格线残留**（比如提示词里误写 `"thin grid lines"`），可以启用连通域过滤：只保留每个 cell 中面积最大的连通区域。

**但代价**：如果角色的头发/武器/披风和身体不连通，会被当杂点丢弃。

**结论**：
- 优先修 prompt 去掉网格线
- 只在无法重新生成、且杂点明显时才启用
- 启用时膨胀半径建议 20-25 px（能把分离的部件重新连起来）

### 技巧 3：顺序映射 vs OCR

永远别用 OCR 识别生成图里的英文标签做映射（乱码率高）。

**正确做法**：
```python
NAMES = ['ryu', 'ken', 'chunli', ...]  # 与 prompt 里列表顺序完全一致
for idx, (row, col) in enumerate(cells):
    name = NAMES[idx]
    save(f'{idx+1:02d}_{name}.png')
```

行列位置 → 列表索引，0 歧义。

### 技巧 4：Contact Sheet 验证

抠完后一定要生成拼图预览肉眼确认。16 张角色摆到一张 4×4 预览图上，问题一目了然。

`contact_sheet.py` 做这件事。

### 技巧 5：迭代开发

调不好阈值时，用这个流程快速迭代：

1. 只对一张 cell 试：`extract_grid.py --only=5`（抠第 5 格）
2. 打印中间数据：`extract_grid.py --debug`（输出 bbox、阈值、像素统计）
3. 调好参数后批量：`extract_grid.py`（抠全部）

## 何时重新生成图，而不是修脚本

脚本无法弥补的问题：

- 生成图里**真的画了**网格线/锚点/文字 → 重新 prompt
- 某个角色画得崩了（歪斜、破相） → 重新跑一次
- 风格严重不一致（前 5 个写实、后 4 个卡通） → 强化风格锚定重跑
- 行高偏差 > 20% → prompt 加 `"manufactured product photograph"` 约束，或降密度

**规则**：如果重新生成一张的成本 < 改脚本的成本，优先重新生成。
